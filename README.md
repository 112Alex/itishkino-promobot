# Промобот «Айтишкино»

Telegram-бот для записи семейных заявок в AlfaCRM. Промоутер или администратор выбирает филиал и отвечает на вопросы о родителе, контактах и детях, проверяет анкету и отправляет её в CRM. Одна семья создаёт одну карточку, а комментарий и полные данные семьи сохраняются отдельной коммуникацией от технического аккаунта. Примечание содержит только дату/время без секунд и «писать», «звонить» или «писать/звонить». Номер заявки записывается только в специальное поле CRM.

Бот сохраняет черновики и очередь в SQLite, переживает перезапуск и сообщает о доставке отдельно от приёма анкеты. Если телефон или Telegram уже есть среди лидов, клиентов либо архивных карточек, заявка передаётся администратору для проверки. Существующие карточки бот не изменяет.

## Как добавить лида

Откройте [@itishkino_promo_bot](https://t.me/itishkino_promo_bot), отправьте `/start` и выберите филиал в меню. Затем отправляйте семью **одним сообщением**, без пошаговой анкеты и кнопки подтверждения:

```text
Мария Игорь 6 Василий 8 +79991234567 @my_parent писать MAX Telegram
Можно написать после 18:00
```

Первое имя — родитель, затем дети с возрастами, контакты в конце первой строки. Всё со второй строки — свободный комментарий. Без контакта заявку не отправляем. По умолчанию с телефоном — писать/звонить, только с Telegram — писать; способ связи можно указать в первой строке. Подробнее: [памятка с примерами](docs/promoter.md).

Корректное сообщение сразу сохраняется и ставится в очередь. «Заявка сохранена» подтверждает приём; «Создано в CRM» — результат записи и проверки. `/mine` показывает отправленные заявки. Все администраторы добавляют лидов так же. Бот редактирует одно сообщение меню и удаляет входящий текст после сохранения в базе. Филиал применяется к новым заявкам; уже отправленные заявки смена филиала не переносит.

## Управление доступом одним сообщением

Администратору доступна команда `/admin`. Например: `/add_promoter 8620489034 Максим` и `/add_admin 8764105122 IT Преображенка`. Для имени — `/rename_promoter ID Имя` или `/rename_admin ID Имя`; `/remove_promoter ID` отключает промоутера. `/promoters` и `/admins` показывают имена, `/watch Преображенка, Кузьминки` задаёт филиалы уведомлений, `/watch все` или `/watch нет` выбирает все либо ни одного.

По username: `/add_promoter @username Имя`. Человек сначала пишет `/start`, администратор подтверждает найденный числовой ID готовой командой из уведомления. Имя сохраняется сразу. Telegram Bot API не позволяет получить произвольный личный аккаунт по username; смена username не переносит доступ.

Первоначальные администраторы — CSV в ENV. Остальные роли, имена и подписки — SQLite, сохраняются при перезапуске и входят в backup. Каждый администратор может добавлять других. Ошибки по заявкам получают подписанные на филиал администраторы, общие сбои — все. Для получения уведомлений нужно один раз отправить `/start`.

Готовые команды переноса образа и обновления Mac Mini через SSH: [инструкция 0.4.0](docs/franchise-upgrade.md). Серверная база и рабочие секреты сохраняются.

## Запуск на сервере через Docker

Нужны Linux, Docker Engine и Docker Compose 2.20+; на DietPi Docker можно поставить через `dietpi-software`. Открывать входящие порты для бота не требуется. Для рабочего бота используйте один экземпляр, включая локально запущенные копии.

Получите проект и перейдите в его каталог:

```sh
git clone https://github.com/112Alex/itishkino-promobot.git
cd itishkino-promobot
```

Подготовьте настройки:

```sh
mkdir -p runtime
cp .env.example runtime/.env
cp config/franchise.example.json runtime/config.json
chmod 700 runtime
chmod 600 runtime/.env runtime/config.json
nano runtime/.env
nano runtime/config.json
```

В `.env` заполните токен BotFather, email технического пользователя CRM и ключ v2api. В `ADMIN_TELEGRAM_IDS` внесите всех первоначальных администраторов через запятую. `ADMIN_TELEGRAM_ID` — необязательный отдельный ID владельца, если он пуст, для диагностики используется первый ID CSV. `promoters` и `administrators` в новом JSON можно оставить пустыми: промоутеры добавляются командами, администраторы заданы в env. JSON `administrators` также поддерживается для переноса старых настроек.

`config/franchise.example.json` содержит Преображенку, Кузьминки, Марьино и Жулебино **этой CRM**. Доступ к четырём филиалам и общие настройки проверены read-only 6 октября; контракт создания проверен реальной записью в Преображенке 3 октября. На остальных филиалах бот проверяет результат каждой записи; первую настоящую заявку дополнительно проверьте в интерфейсе CRM. Для другой CRM используйте `config/production.example.json` и пройдите [приёмку](docs/integration.md). Не переносите флаги проверки на другой аккаунт/филиал автоматически.

Контейнер работает от UID/GID 10001. После редактирования настройте владельца файлов и запустите:

```sh
sudo chown 10001:10001 runtime/.env runtime/config.json
docker compose build
docker compose run --rm bot network-check
docker compose run --rm bot doctor
docker compose up -d
docker compose logs --tail=50 bot
```

Команда `network-check` проверяет CRM login, Telegram getMe и наличие webhook, без отправки сообщений, polling и создания лидов. `doctor` дополнительно показывает состояние очередей. После запуска все администраторы должны открыть бота и нажать `/start`.

Для Intel Mac Mini 2011 подготовлен образ `itishkino-promobot:0.4.0-amd64` под Linux/DietPi, без эмуляции. Compose ограничивает бот 256 МБ RAM и 0,75 CPU; SQLite на SSD и один процесс обслуживают четыре филиала. Анкеты разных промоутеров независимы, CRM-доставка выполняется последовательно с настройками конкретной заявки. Готовый архив загружается через `docker load -i itishkino-promobot-0.4.0-linux-amd64.tar.gz`. После загрузки сборку пропустите, запускайте `docker compose up -d --no-build`. Архив образа хранится отдельно от Git, его повторная сборка и экспорт: `sh scripts/build-image.sh`. Подробнее: [инструкция переноса](docs/docker.md).

Для переноса настроек текущего рабочего аккаунта используйте свои защищённые env/JSON, а не заново заполненные примеры. Контейнерные пути из `.env.example` оставьте как указано. **Перед запуском на сервере остановите локальную копию этого Telegram-бота.** Порядок переноса данных, резервных копий и VPN: [Docker на DietPi](docs/docker.md).

База и резервные копии находятся в постоянном Docker volume `data`. Пересборка образа их сохраняет. `docker compose down` останавливает бот; **`down -v` удаляет данные**.

## Обслуживание

```sh
docker compose ps
docker compose logs --tail=100 bot
docker compose run --rm bot doctor
docker compose run --rm bot network-check
docker compose run --rm bot backup
docker compose restart bot
```

Копия SQLite создаётся штатным API базы данных, с проверкой целостности. [Инструкция Docker](docs/docker.md) описывает выгрузку копии, ежедневный backup и обновления. Telegram-proxy задаётся только через `TELEGRAM_PROXY`; запросы к CRM идут напрямую.

## Локальная разработка и mock

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install --no-deps .
cp .env.mock.example .env.test
chmod 600 .env.test
.venv/bin/promobot --env .env.test doctor
.venv/bin/promobot --env .env.test integration-test
.venv/bin/python -m pytest -q
```

Mock не обращается к рабочей CRM. Без Telegram-токена ответы сохраняются только в локальном outbox. Для приёмки используйте отдельную БД, которую не запускаете потом с рабочим ботом. Тесты не создают карточки в реальной CRM. `requirements.lock` фиксирует зависимости разработки, `requirements.runtime.lock` — только рабочие зависимости образа.

## Как устроен проект

Python 3.11–3.12, aiogram 3, httpx и aiosqlite. `dialog.py` ведёт анкету; `members.py` управляет доступом промоутеров; `storage.py` хранит события, черновики и очередь; `worker.py` проверяет совпадения, доставляет и сверяет карточку; `crm.py` работает с API; `telegram.py` принимает обновления и отправляет сохранённые ответы. SQLite использует WAL, foreign keys и `synchronous=FULL`.

Неопределённый результат записи сначала сверяется по номеру заявки; слепого повторного создания нет. Поиск дублей и создание — разные API-запросы: параллельное ручное создание менеджером оставляет окно гонки. Приёмку интерфейса CRM, серверной сети и перезагрузки DietPi нужно выполнить на месте. GitHub Actions проверяет Python 3.11/3.12 и сборку Docker.
