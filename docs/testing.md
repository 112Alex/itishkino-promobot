# Отчёт проверки — 5 октября 2026

## Автоматические тесты

**118 passed** на CPython **3.11.14** и **3.12.14**, Linux x86_64. Проверены анкета, возможность владельца добавлять лидов без роли промоутера, три администратора, добавление/отключение промоутеров по ID, подтверждение username, смена username, защита от устаревших кнопок и межфилиального доступа, пагинация списка, истечение сессии, сохранение роли после перезапуска, уведомления каждому администратору без рекурсивных ошибок, read-only диагностика сети, доступ только в личных чатах, сохранение событий и очередей, дубли, повторные попытки, восстановление, автор комментария и начальный этап CRM.

Тесты используют вымышленные данные и mock HTTP. Один интеграционный тест проходит через настоящий localhost HTTP-сокет aiohttp + httpx. В рабочей CRM обычные тесты ничего не создают.

## Docker

Образ `itishkino-promobot:0.2.0-amd64` (Linux amd64, версия 0.2.0) успешно собран на Python 3.12 slim-bookworm; `pip check` не нашёл конфликтов. Проверены CLI и Compose-конфигурация. Базовый образ закреплён по digest, runtime-зависимости по версиям.

Контейнер под UID/GID 10001, с read-only корнем, без capabilities, без внешней сети и с `no-new-privileges`, лимитами 256 МБ / 0,75 CPU / 64 PID прошёл добавление двух промоутеров через диалог (ID и username с подтверждением), полную mock-анкету, сохранил одну карточку и один комментарий (`delivered`). Следующий контейнер использовал ту же базу через volume: роли двух промоутеров, доступ трёх администраторов и доставленная заявка сохранились. Пиковая RSS Python в этом синтетическом сценарии — 34,3 МБ; это не замер полной нагрузки на Mac Mini. Backup создан, `PRAGMA integrity_check` вернул `ok`. Рабочий образ не содержит тестовых зависимостей, секретов, локальных конфигураций и баз. Подготовлен переносимый `docker save` архив (~66 МиБ) и SHA256SUMS в локальном `outputs/`; бинарный архив не включён в Git. Повторная сборка: `sh scripts/build-image.sh`.

`.env.example` предназначен для prod/real Docker и оставляет секреты/ID владельца пустыми. Для локального mock используется `.env.mock.example`. Текущий рабочий бот пока запущен вне Docker; миграция на сервер выполняется владельцем по [инструкции](docker.md).

## Реальная CRM и Telegram

С разрешения владельца создана ровно одна тестовая карточка 888 и один комментарий 1551. Проверены контакты, семейное примечание, custom-номер заявки, начальный этап, отсутствие ответственного/педагогов, автор коммуникации и отдельный поиск дублей по телефону/Telegram. Повторная обработка не добавила записей. Подробности: [акт приёмки](crm-acceptance.md).

5 октября read-only проверка текущих рабочих настроек подтвердила CRM login, Telegram getMe и отсутствие webhook; сообщений, getUpdates и новых карточек не было. Проверка выполнена из текущего хоста; ранее локальный polling подтвердил доступность Telegram. Полная анкета настоящим пользователем ещё требует проверки.

## Ограничения проверки

DietPi на Mac Mini, его производительность, серверная сеть Amnezia, выход контейнера через настольный VPN, перезагрузка сервера и внешний интерфейс CRM на месте ещё не проверены. Для контейнера добавлена команда `network-check`; экспорт Amnezia/его протокол и версия ещё не предоставлены. Шаблоны systemd и shell-скрипты проверялись локально; на сервере их не устанавливали.

В sandbox локальный поток aiosqlite не будил event loop; соответствующие CLI и pytest выполнены вне sandbox. Это ограничение среды не устранялось заменой SQLite. Файловая система рабочего каталога не соблюдает chmod, поэтому настоящие секреты и БД размещены в защищённом каталоге пользователя, а Docker-тест использовал Linux volume.
