# Отчёт проверки — 3 октября 2026

## Автоматические тесты

**96 passed** на CPython **3.11.14** и **3.12.14**, Linux x86_64. Проверены анкета, возможность владельца добавлять лидов без роли промоутера, дополнительный администратор, доступ только в личных чатах, сохранение событий и очередей, дубли, повторные попытки, восстановление, автор комментария и начальный этап CRM.

Тесты используют вымышленные данные и mock HTTP. Один интеграционный тест проходит через настоящий localhost HTTP-сокет aiohttp + httpx. В рабочей CRM обычные тесты ничего не создают.

## Docker

Docker-образ успешно собран на Python 3.12 slim-bookworm; `pip check` не нашёл конфликтов. Проверены CLI и Compose-конфигурация. Базовый образ закреплён по digest, runtime-зависимости по версиям.

Контейнер под UID/GID 10001, с read-only корнем, без capabilities и с `no-new-privileges` прошёл полную mock-анкету, сохранил одну карточку и один комментарий (`delivered`). Следующий контейнер использовал ту же базу через volume. Backup создан, `PRAGMA integrity_check` вернул `ok`. Рабочий образ не содержит тестовых зависимостей, секретов, локальных конфигураций и баз.

`.env.example` предназначен для prod/real Docker и оставляет секреты/ID владельца пустыми. Для локального mock используется `.env.mock.example`. Текущий рабочий бот пока запущен вне Docker; миграция на сервер выполняется владельцем по [инструкции](docker.md).

## Реальная CRM и Telegram

С разрешения владельца создана ровно одна тестовая карточка 888 и один комментарий 1551. Проверены контакты, семейное примечание, custom-номер заявки, начальный этап, отсутствие ответственного/педагогов, автор коммуникации и отдельный поиск дублей по телефону/Telegram. Повторная обработка не добавила записей. Подробности: [акт приёмки](crm-acceptance.md).

Telegram getMe проверен, webhook отсутствует; локальный polling подтвердил доступность Telegram. Полная анкета настоящим пользователем ещё требует проверки.

## Ограничения проверки

DietPi, серверная сеть AWG, перезагрузка сервера и внешний интерфейс CRM на месте ещё не проверены. Шаблоны systemd и shell-скрипты проверялись локально; на сервере их не устанавливали.

В sandbox локальный поток aiosqlite не будил event loop; соответствующие CLI и pytest выполнены вне sandbox. Это ограничение среды не устранялось заменой SQLite. Файловая система рабочего каталога не соблюдает chmod, поэтому настоящие секреты и БД размещены в защищённом каталоге пользователя, а Docker-тест использовал Linux volume.
