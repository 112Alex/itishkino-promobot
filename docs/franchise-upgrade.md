# Обновление до 0.4.0: четыре филиала и новое меню

Лиды вводятся одним текстовым сообщением: родитель, дети с возрастами и контакты в первой строке; свободный комментарий со второй. Кнопки пошаговой анкеты и подтверждения убраны. Корректное сообщение сразу попадает в сохранённую очередь CRM. Выбор филиала остаётся в меню; ошибки разбора не создают заявок. [Примеры ввода](promoter.md).

Текстовые сообщения и команды пользователя удаляются после сохранения события и обработки в SQLite; неподдерживаемые вложения остаются. Если Telegram временно недоступен, удаление повторяется через очередь и не блокирует меню. Результат доставки и ошибки приходят отдельно.

В CRM используются филиалы: Преображенка — 4, Кузьминки — 3, Марьино — 2, Жулебино — 1. Для них общий канбан «Основная» (1), начальный этап «Не разобрано» без назначения, источник «Промо со Стивом» (6), технический пользователь (18), поле `custom_promo_request_id`. Проверка 6 октября 2026 подтвердила доступ аккаунта к четырём филиалам, воронке, источнику и полю номера заявки без записи новых карточек. Контракт создания ранее проверен в Преображенке; реальные новые заявки в остальных филиалах нужно проверить в интерфейсе CRM. После каждой записи бот самостоятельно сверяет филиал, контакты, этап, источник и коммуникацию.

## Что получат пользователи

Промоутер выбирает филиал только в главном меню, затем отправляет семью одним сообщением. У каждого выбранный филиал свой. Два промоутера могут одновременно добавлять лидов; очередь доставляет их последовательно с отдельными настройками каждой заявки. Поиск совпадений выполняется в выбранном филиале, включая архив.

Администраторы добавляют лидов тем же способом. Управление доступом — текстовыми командами с ID и именем в одном сообщении:

```text
/admin
/add_promoter 8620489034 Максим
/add_admin 8764105122 IT Преображенка
/rename_promoter 8620489034 Максим Иванов
/rename_admin 8764105122 IT Преображенка
/promoters
/admins
/watch Преображенка, Кузьминки
/watch все
/watch нет
```

Это команды **в чате Telegram-бота**, не в SSH-терминале. В примерах добавления используются реальные ID ранее указанных аккаунтов. Для других людей укажите их ID и имя. `/remove_promoter ID` отключает промоутера; заявку и историю не удаляет, администратора не отключает. Список показывает имена. `/promoters 2` и `/admins 2` открывают следующую страницу списка.

По username: `/add_promoter @username Имя`. Человек отправляет `/start`, после чего бот даёт готовую команду `/approve_promoter` с номером приглашения и найденным ID. Доступ закрепляется за числовым ID после проверки. Отмена — готовая команда `/cancel_invite` из сообщения бота. Имя сохраняется вместе с приглашением.

`/watch` показывает текущие подписки; список филиалов через запятую задаёт новый набор целиком. По умолчанию выбраны все филиалы. Ошибки/совпадения заявок идут подписанным администраторам, общие сбои сервиса — всем. Подписки сохраняются в базе. `/problems` показывает проблемные заявки, `/request номер` — подробности, `/retry номер` — повторную безопасную сверку; совпадение не разрешает автоматического создания.

Первоначальные администраторы задаются в `ADMIN_TELEGRAM_IDS` через запятую. `ADMIN_TELEGRAM_ID` остаётся совместимым необязательным ID владельца; если пусто, владелец для диагностики — первый ID CSV. Добавленные командами роли, имена и подписки хранятся в SQLite. Всем администраторам нужно написать `/start`, чтобы Telegram разрешил отправку уведомлений.

## Обновление работающего Mac Mini

База с заявками, промоутерами и подписками уже находится на сервере. Для этого обновления переносить SQLite с ПК не нужно; рабочая серверная база сохраняется.

На основном ПК готовый образ расположен в `/mnt/storage/python/bot_for_leads/outputs/itishkino-promobot-0.4.0-linux-amd64.tar.gz`. Создайте `transfer` на сервере и отправьте архив вместе с `outputs/SHA256SUMS`. Если подключение идёт через локальный SOCKS Tailscale на 1055:

```sh
ssh -o 'ProxyCommand=nc -X 5 -x 127.0.0.1:1055 %h %p' root@100.116.241.99 'mkdir -p /root/tg-bots/itishkino-promobot/transfer'
scp -o 'ProxyCommand=nc -X 5 -x 127.0.0.1:1055 %h %p' \
  /mnt/storage/python/bot_for_leads/outputs/itishkino-promobot-0.4.0-linux-amd64.tar.gz /mnt/storage/python/bot_for_leads/outputs/SHA256SUMS \
  root@100.116.241.99:/root/tg-bots/itishkino-promobot/transfer/
```

При другом способе SSH используйте тот же маршрут/ProxyCommand, через который уже подключились. Секреты и конфигурация VPN в образ не включены.

Дальше **на Mac Mini через SSH** скопируйте весь блок. Он обновляет уже работающий бот с четырьмя филиалами; ENV и VPN менять не нужно. При ошибке последующие команды блока не выполняются, SSH-сессия остаётся открытой.

```sh
(
  set -e
  cd /root/tg-bots/itishkino-promobot
  docker compose -f compose.yaml -f compose.vpn.yaml stop bot
  docker compose -f compose.yaml -f compose.vpn.yaml run --rm bot backup
  git pull --ff-only
  (cd /root/tg-bots/itishkino-promobot/transfer && sha256sum -c SHA256SUMS)
  docker load -i /root/tg-bots/itishkino-promobot/transfer/itishkino-promobot-0.4.0-linux-amd64.tar.gz
  docker compose -f compose.yaml -f compose.vpn.yaml run --rm bot network-check
  docker compose -f compose.yaml -f compose.vpn.yaml up -d --no-build bot
  docker compose -f compose.yaml -f compose.vpn.yaml logs --tail=50 bot
)
```

Для первого перехода на четыре филиала обновите рабочие runtime-файлы скриптом ниже. Команды уже содержат ID IT-аккаунта 8764105122 и готовы к копированию. Если четыре филиала уже работают, этот шаг можно пропустить. Скрипт сохранит владельца и остальных администраторов, которые уже находятся в ENV/старом JSON, добавит указанный ID, добавит четыре филиала. Токен, CRM email/API-ключ, proxy, старые промоутеры и настройки текущего филиала сохраняются. Резервные копии JSON/ENV создаются в том же закрытом каталоге. База и VPN-конфигурация этим скриптом не изменяются.

```sh
python3 /root/tg-bots/itishkino-promobot/scripts/upgrade-franchise.py --runtime /root/tg-bots/itishkino-promobot/runtime --admin-id 8764105122 --dry-run
python3 /root/tg-bots/itishkino-promobot/scripts/upgrade-franchise.py --runtime /root/tg-bots/itishkino-promobot/runtime --admin-id 8764105122
```

Если используете `PROMOBOT_RUNTIME_DIR`, замените `--runtime runtime` на фактический закрытый каталог. Скрипт предназначен для этой CRM с текущей Преображенкой (4), воронкой (1) и источником (6); при несовпадении отказывается менять файлы. Для нового запуска с нуля используйте `config/franchise.example.json` и `.env.example`.

Проверки и запуск:

```sh
docker compose -f compose.yaml -f compose.vpn.yaml run --rm bot branch-check
docker compose -f compose.yaml -f compose.vpn.yaml run --rm bot network-check
docker compose -f compose.yaml -f compose.vpn.yaml up -d --no-build bot
docker compose -f compose.yaml -f compose.vpn.yaml logs --tail=50 bot
```

`branch-check` не создаёт лидов, не отправляет Telegram-сообщений, не выводит контакты/ключи. `network-check` должен показать `crm: ok`, `telegram: ok`, `webhook_present: false`. VPN используется уже настроенный; менять его образ и ключи для этого обновления не требуется.

При обновлении с 0.3.2 миграция 6 сохраняет имена приглашённых промоутеров и сбрасывает временные старые сессии ввода администратора. Прежние черновики, заявки, очередь, роли и DB identity сохраняются. Перед миграцией создаётся `before-migration-6.sqlite3`. Старые незавершённые анкеты можно заменить новым полным сообщением; уже подтверждённые заявки доставляются без изменения payload. Локальная копия бота должна оставаться остановленной; один токен обслуживается одним polling-процессом.

После запуска отправьте `/start` и выберите подписки. Проверка вдвоём: первый промоутер создаёт заявку в Преображенке, второй — в Кузьминках; проверьте филиалы карточек CRM, имена промоутеров в меню и личные подписки администраторов. Не вводите вымышленные заявки в рабочую CRM без намерения сохранить их там.

## Формат CRM в 0.4.0

Примечание новой заявки содержит только дату и время подтверждения по Москве без секунд и следующей строкой «писать», «звонить» или «писать/звонить». Например:

```text
06.10.2026 18:04
писать/звонить
```

Исходный комментарий, полные данные семьи, контакты и мессенджеры находятся в одной коммуникации. Метки с ID заявки в ней нет; ID остаётся только в `custom_promo_request_id`. Даже при пропуске свободного комментария создаётся одна коммуникация с данными семьи.

Перед созданием коммуникации бот сохраняет список уже существующих коммуникаций и фазу операции в SQLite. После ответа API сохраняет конкретный communication ID. При потерянном ответе ищет точное новое совпадение вне сохранённого списка с нужным автором и типом; отсутствие/неоднозначность требуют проверки вместо повторного создания. Незавершённые заявки старого формата сохраняют первоначальный payload, чтобы проверка уже выполненной записи после обновления не давала ложное расхождение.
